## 第 2 步：`convert` —— 把 B 站视频变成"音频 + 关键画面 PDF"（Gate 2）

### 它现在能做什么
```bash
bili2nb convert "https://www.bilibili.com/video/BV1GJ411x7h7"
```
一条命令（**不需要登录 Google**）就会：
1. 检查链接是否安全（只认 bilibili.com / b23.tv，别的域名一律拒绝，防止被骗去访问奇怪的地址）；
2. 只下载**音频流**（不下整段视频），检查时长有没有被截断、能不能正常解码；
3. 单独下一份 ≤720p 的画面，挑出"有内容的关键画面"，做成 PDF：封面有标题、作者、原链接、日期、时长；每页一张截图，页首有可点击的时间戳（点一下直接跳到 B 站那个时间点），还有书签目录；
4. 把结果放进 `output/<视频编号>/`：`audio.m4a`、`keyframes.pdf`、`manifest.json`（记录这次处理的全部细节，不含任何密码/Cookie）。

可选参数：`--frames auto|slides|scene|none`（选图方式）、`--part N`（多集视频选第几集）、`--audio-only`（只要音频）、`--output 目录`、`--json`（给程序读的结果）。没做完的功能（比如 `--keep-files`）故意不在 `--help` 里显示。

### 真实测试结果（用的都是公开视频，只在你电脑上处理）
| | 短视频（官方 MV，3分半） | 软件演示（PPT 教程合集的第 5 集，3分20秒） |
|---|---|---|
| 音频 | 5.4 MB，时长误差 0.09 秒 | 3.2 MB，时长误差 0.02 秒 |
| PDF | 9 页，0.8 MB | 9 页，1.4 MB |
| 总耗时 | 33 秒 | 24 秒 |
| 下载量 | 52 MB | **只有 8.8 MB**（合集有 30 集，只下了你指定的那一集） |

- 音频是 B 站原本的 AAC 格式，**原样保留没有重新压缩**（NotebookLM 本来就支持，没必要损失音质）。
- 软件演示那份 PDF 里，每张截图正好对应一个操作步骤（打开文件夹 → 打开 PowerPoint → 插入音频），界面上的字能看清。**请你自己打开看一眼**：`tmp/gate2/final/` 下面。
- b23.tv 短链接也试过了，会安全地跳转到正确的视频。

### 选图是怎么挑的（大白话）
- **幻灯片模式**：每 2 秒看一眼缩小的画面。画面"稳定下来"后才算一页；同一页如果后来内容变多（比如 PPT 一条条出现），取最完整的那一刻；全黑、淡入淡出的过渡画面丢掉；翻回来的重复页也丢掉。
- **MV 这类一直在动的画面**：幻灯片模式找不到稳定画面，程序会**如实警告**并改成每隔一段时间均匀取一张，不会假装"这视频没有画面"。
- 最多 150 张，超了会均匀抽稀并提示。

### 遇到的问题和修复（测试帮我抓到的）
1. **短视频会"没有画面"**：兜底的定时取帧，视频短于 15 秒时算出 0 个时间点，会误报"无画面"。已修好，并加了测试锁住。
2. **错误信息看不懂**：视频不存在、分集编号超出时，下载工具只会报 `KeyError('bvid')`。现在先问 B 站的公开接口，直接说"视频不存在"或"该视频只有 30 个分 P，没有 P99"。
3. **缺少 CID**：下载工具不给视频的 CID（分 P 的唯一编号），改从 B 站公开接口取，用来组成唯一编号（BV号+CID）。
4. **标题重复**：多集视频标题里分集名出现了两遍，已去重。

### 出错时的表现（都是真的跑过）
| 情况 | 结果 |
|---|---|
| 链接不是 B 站 / 不是单个视频 | 报 `INVALID_URL`，立刻结束 |
| 视频不存在 / 分集越界 | 报 `VIDEO_UNAVAILABLE`，说清原因 |
| 没装 ffmpeg | 报 `TOOL_MISSING`，提示 `brew install ffmpeg`，**一个字节都没下载就停** |
| 音频被截断、解不开、磁盘不够 | 报对应错误，**不会留下半成品**，临时文件自动清理 |

### 还没做的（诚实说明）
- 30–60 分钟的长视频、PPT 课件讲座：留到 Gate 4 测，并统计"该保留的 PPT 页有没有漏"。
- Ctrl+C 中断、B 站限速这类真实场景：目前只有自动测试，Gate 4 再真实测。

## 第 3 步：`import` —— 从链接一步到 NotebookLM（Gate 3，进行中）

### 现在有哪些命令
```bash
bili2nb import  <B站链接>       # 转换 + 新建笔记本 + 上传音频与PDF + 等到"可用" + 打印笔记本网址
bili2nb status  <任务号>        # 看某次任务的结果（笔记本网址、来源编号、出错原因）
bili2nb retry   <任务号>        # 失败/中断后接着做，不会重复建本、不会重复上传
bili2nb jobs                    # 本机历史任务列表
```
`import` 额外支持 `--keep-files`（成功后保留本地音频/PDF）、`--force-new`（明确要为同一视频再建一个笔记本）。

### 它是怎么保证"不乱来"的（大白话）
- **先查登录，再下载**：没登录会在下载任何东西之前就报 `AUTH_REQUIRED`，不会白下一大堆视频。命令行里手动运行时会问你要不要现在登录；加了 `--json` 或被程序调用时**绝不弹问题**。
- **每一步都记在小本本里**（本机数据库）：建好笔记本立刻记下编号，每个文件上传完立刻记下来源编号。
- **重复运行同一个视频**：直接告诉你"已经导入过"并给原来的笔记本网址，**不会新建**。想要新的才加 `--force-new`。
- **失败了怎么办**：比如 PDF 传失败了，`retry` 会接着传 PDF，**音频不会再传一遍，笔记本也还是原来那个**。Ctrl+C 中断同理，会提示你 `bili2nb retry 任务号`。
- **云端出错重试有上限**：被限流时等 5 秒、再等 15 秒，最多试 3 次就停，保留任务等你 retry，绝不无限重试。
- **建笔记本最怕"重复"**：如果网络在"创建笔记本"时断了，程序会先去找有没有刚建好的新笔记本，找到就用；找不到也**不会自动重试**，而是告诉你先去看一眼有没有同名新笔记本——这是 Gate 1 里"回执丢了但其实成功了"的教训。
- **成功后清理**：默认把本地的音频/PDF 删掉省空间（笔记本里已经有了）；加 `--keep-files` 或 `--output 目录` 就留着。失败时一律保留，方便排查。

### 第一次真实导入：出了两个问题（如实记录）

**问题 1：多建了一个重复的空笔记本（我们的缺陷，已修）**
- 现象：运行 `import` 后你的账号里多出**两本同名笔记本**，创建时间只差 2 秒。一本是任务记录的，另一本是重复的空本子。
- 原因：创建笔记本时网络回执丢了，而我们依赖的工具包（notebooklm-py）**自己偷偷重试了一次**——"创建"这种操作不能随便重试，重试就等于再建一本。我之前写的"防重复"只管了工具包之外的那一层，管不到它内部的重试。
- 修复：创建笔记本时把工具包的自动重试关掉；网络出错时由我们自己先去找"是不是已经建好了"。同时补了 4 个专门的回归测试（修之前它们全部报错，修之后通过）。
- **这个重复的空笔记本我没有删**（删除要你同意）。它是空的，不影响使用，你可以在网页上直接删掉：`9159a9e2…`（同名的另一本 `4e8482dd…` 才是任务在用的）。

**问题 2：你电脑到 Google 的网络现在不稳定（环境问题，不是代码）**
- 我用最普通的命令 `curl https://www.google.com/` 测试，10 次里有 7 次"文件只传了一半就断了"。工具包里的网络请求也是同样 6/8 失败。
- 你的电脑没有开系统代理，但有好几个虚拟网卡（像是 VPN/代理类软件）。**我不会去改任何网络或代理设置**，这属于你的环境。
- 代码这边已经按设计工作：出错时等 5 秒、再等 15 秒，最多试 3 次就停，任务保持"可恢复"状态，没有无限重试，也没有再乱建笔记本。
- 我在后台每分钟探测一次网络，稳定后会自动对**同一个任务**执行 `retry`（还在你同意的范围内）。如果一直不稳定，可能需要你检查一下代理/VPN 的节点，换个稳定的再告诉我。

## Gate 4 长视频导入 & 重复建本的真正原因
- 38 分钟讲座真的导进 NotebookLM 了：音频 37 MB + PDF，两个来源都 READY，上传一次成功，没有重试。
- 为什么能成：之前大文件一次性上传会在约 8 秒时被断开。现在改成每 2 MB 一块上传，每块出问题先问服务器"收到多少了"，再从那里接着传。
- 又发现一次重复建本（同名空笔记本）。这次查到了真正原因：底层网络库 libcurl 在"老连接突然断开"时，会悄悄把请求再发一遍；Google 其实已经处理了第一遍，于是建了两个笔记本（上传时多出来一个卡住的空来源也是这个原因）。我用本地小程序复现了这件事（服务端收到 2 次，改后 1 次）。
- 修法：创建笔记本和上传时每次都用全新连接，不让它偷偷重发。
- 还差：用一次真实导入确认现在只建 1 个笔记本。账号里有 2 个修复前留下的空重复笔记本（我没删，等你决定）。

## 你发现的 PDF 封面乱码
你在手机上看到的乱码是真的：封面用的中文字体没有"装进"PDF 里，电脑上的阅读器会借用本机字体所以正常，NotebookLM 没有这个字体就显示乱码。我之前只检查了"文字能不能提取出来"，没发现这个问题。现在改成把字体子集直接装进 PDF（几十 KB），重新生成后封面中文清晰。已经传到你笔记本里的那两份旧 PDF 还是旧的，等你同意后再替换。
