### 2.2 Git 历史审计（只读，未重写）
- **当前历史**（`main`，现为 8 个提交）：对全部提交的全部 blob 扫描（完整笔记本链接/UUID、`/Users/<name>`、常见邮箱域、令牌特征、"仅限私人查看"类遗留措辞）：**无凭证、无邮箱**；唯一命中的令牌特征是测试里"输出不应包含 SAPISID"的断言。提交身份使用 GitHub noreply 邮箱。
- **残留风险**：仓库公开前我曾做过一次历史压缩并强制推送（在本次任务之前）。GitHub 上**旧提交仍可通过 SHA 访问**（已用 API 实测 `771d225`、`65bce55`、`be46f79`、`fa115a1` 返回 200）。这些旧提交含：4 处**完整笔记本链接**（均指向 2 个仍存在的笔记本）和 3 处本机绝对路径（暴露本机用户名）。**不含任何 Cookie、令牌或登录文件。**
- **风险评估**：低。笔记本链接需要该 Google 账号的访问权限才能打开；路径只泄露本机用户名。
- **按要求未擅自处理**，建议使用者三选一：① 接受低风险；② 在 NotebookLM 里删除这 2 个笔记本（链接立即失效）；③ 向 GitHub Support 申请清除缓存的悬空提交（并视需要再重写历史，这属于破坏性操作，需使用者明确授权）。

### 2.3 CI 审计
原配置的问题：`doctor` 被 `continue-on-error` / `|| true` 吞错；未登录命令用 `|| echo` 吞掉任意失败；只有 Python 3.12；没有声明权限；第三方 Action 用可移动的标签；没有验证 `--json` 的纯净性。

### 2.4 SDK 审计
`notebooklm-py==0.8.6` 的私有依赖共 9 项（见 [SDK_PRIVATE_API.md](SDK_PRIVATE_API.md)）。发现的真实风险：
1. 分块上传的安装函数在 SDK 结构变化时**返回 False**，随后 SDK 静默使用不可靠的单请求上传；
2. 连接控制通过**全局替换 `curl_cffi.requests.AsyncSession`** 实现，作用范围过大；
3. 孤儿来源清理以"同名 + PREPARING/ERROR"为依据，**可能误删用户自己上传的同名来源**。

### P1 SDK 兼容与孤儿归属
| 改动 | 文件 |
|---|---|
| **SDK 兼容守卫**：固定 0.8.6 + 私有接口能力检查；不满足则在**任何云端写入之前**返回 `SDK_INCOMPATIBLE`（退出码 26）；版本不同可用 `BILI2NB_ALLOW_UNVERIFIED_SDK=1` 放行，**接口检查不可绕过**；`doctor` 增加 `sdk-compat` 项 | `notebook/sdk_compat.py`、`doctor.py` |
| **不再静默降级**：分块上传无法安装时直接报错，不退回单请求上传 | `notebook/chunked_upload.py` |
| **限定连接控制范围**：不再替换 `curl_cffi.AsyncSession`；仅对"上下文内创建的 SDK `CurlCffiAsyncClient`"通过其 `session_factory` 钩子注入 `FRESH_CONNECT/FORBID_REUSE`；引用计数 + 锁，嵌套/并发安全，调用方显式传入的 factory 优先 | `notebook/adapter.py::_fresh_connections` |
| **孤儿归属证据**：只删 ① 任务记录里持久化的来源 ID ② 本次调用期间新出现且同名且卡住的来源 ③ SDK 异常自带的 `source_id`；READY/PROCESSING 永不删；删不掉的 ID 记入 `jobs.orphans`（含对旧数据库的自动迁移），下次重试再清理；`import --json` 的状态里可见 `orphan_source_ids` | `adapter.py`、`jobs/db.py`、`importer.py` |
| 非幂等写入：创建笔记本与上传都**只发送一次**，网络断开后先核对云端（最长 90 秒）再决定，绝不盲重试；SDK 非网络类异常一律报 `UPLOAD_FAILED`，不会假报成功 | `adapter.py` |

回归测试（`tests/unit/test_v11_hardening.py` 等，共 30 余项）覆盖：用户自己的同名卡住来源**永不被删**（成功/失败两种路径）、已记录的孤儿被清理、已记录 ID 后来变 READY 则不删、调用期间的"孪生"来源被清理而 READY 不动、异常 `source_id` 孤儿、删不掉时记录并下次重试、**服务端已接收但响应丢失且列表延迟可见→复用而非重传**、云端确无文件→只尝试一次并报可重试码、重复的 READY 来源只复用第一个、创建笔记本响应丢失只发一次、SDK 版本/签名/接口缺失/libcurl 选项缺失均安全失败、孤儿证据跨进程持久化与旧库迁移，以及作用域补丁的复原/重入/多线程。

**变异测试**（人为破坏代码，确认测试会报警）：① 去掉归属证据校验 → 5 项测试失败；② 去掉上传前的 SDK 兼容检查 → 1 项失败；③ 改回全局替换 `curl_cffi` → 10 项失败；均已还原。

## 6. 残余风险
1. **Windows / Linux 真实 Google 登录与真实 NotebookLM 导入未验证**（CI 无账号）。macOS 已完整验证。
2. **notebooklm-py 是非官方库**，Google 接口随时可能变化；兼容守卫能"安全失败"，但无法让功能继续可用。升级前请走 [SDK_PRIVATE_API.md](SDK_PRIVATE_API.md) 的检查清单。
3. **孤儿来源的"调用期间新出现 + 同名 + 卡住"证据**在极端情况下（你恰好在同一秒从网页上传同名文件）仍可能误判；已把窗口压到单次调用内，并要求状态为卡住。
4. §2.2 的旧提交残留（低风险，待使用者决定）。
5. 旧版本创建的孪生/孤儿来源若未记录 ID，不会被自动清理（只会因归属不明而保留，宁可少删）。
6. Python 3.13 / 3.14 / 3.15 未纳入 CI（本地曾测过 3.14.7）。
